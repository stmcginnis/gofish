# Gofish agent guide

Gofish is a Go client library for DMTF Redfish and SNIA Swordfish. Most of
the code is generated from the published JSON schemas, and changes to it go
through the generator, its config, or hand-written companion files. Read this
before changing anything under `schemas/`, `serviceroot*.go` or `oem/`.

## Layout

| Path | Contents |
|---|---|
| `client.go` | Connection, sessions, HTTP handling (hand-written). |
| `serviceroot.go` | The service root, generated. `serviceroot_custom.go` holds the hand-written additions. |
| `schemas/<schema>.go` | One generated file per schema. |
| `schemas/<schema>_custom.go` | Hand-written code for that schema's types. |
| `schemas/{client,collection,entity,http,odata,resolvedlink,task_monitor,testclient,testutil,types,utils}.go` | Hand-written infrastructure: object fetching, collections, link resolution, the test client, conversion helpers. |
| `oem/<vendor>/` | Vendor `Oem` extensions (`ami`, `dell`, `hpe`, `smc`, `zt`). |
| `tools/generator/` | The schema generator, a separate Go module. See its README. |

## Never edit generated files

A file that starts with `// Code generated by generate-schemas. DO NOT EDIT.`
is overwritten by `make generate`, and CI fails if the committed copy differs
from what the generator produces. Make the change in one of these places
instead:

| Change | Where |
|---|---|
| Field has the wrong Go type, pointer-ness or JSON tag | `FieldOverrides` in `tools/generator/internal/config/config.go` |
| A vendor sends a field with the wrong JSON type (number as string, object instead of array) | `LenientFields` in the generator config, with a converter |
| Type name collides with another schema's type | `TypeRenames` or `TypeOwners` in the generator config |
| Extra field the library populates itself | `ExtraFields` in the generator config, filled by a `postUnmarshal` hook |
| Extra method or helper on a schema type | `schemas/<schema>_custom.go` |
| Decode something the generated `UnmarshalJSON` does not | a `postUnmarshal` hook in `schemas/<schema>_custom.go` |
| Change the behavior of a generated method | copy it into `schemas/<schema>_custom.go` and edit it there |
| Vendor `Oem` properties or actions | `oem/<vendor>/` |
| Generator bug that affects many types | `tools/generator/`, committed with the regenerated output |

After changing generator config or code, run `make generate` and commit the
regenerated files with the change. The generator skips any type, function,
method or constant that a hand-written file in the same package declares, so
adding a declaration to a `_custom.go` file replaces the generated one on the
next `make generate`. `tools/generator/README.md` describes every config
setting.

## Custom JSON decoding

Prefer, in this order:

1. **`LenientFields`** when a vendor sends one field with the wrong JSON type.
   The entry is `"Type.Field": "converter"`; the generated `UnmarshalJSON`
   decodes that field as `any` and assigns `converter(value)`. A converter is a
   `func(any) T` in package `schemas`. Use `toInt`, `toFloat32`, `toFloat64` or
   `parseString` from `schemas/utils.go`, or write a type-specific one in the
   type's `_custom.go` file (see `powerControls` in `power_custom.go`).
2. **A `postUnmarshal` hook** when you need to decode more than the generated
   code does: an extra field, an `@Redfish.AllowableValues` list, a fallback
   link location. The generated `UnmarshalJSON` decodes the type, fills every
   link and action target, then calls the hook:

   ```go
   // postUnmarshal records the allowed reset types.
   func (c *Chassis) postUnmarshal(b []byte) error {
   	var t struct {
   		Actions struct {
   			Reset struct {
   				AllowedResetTypes []ResetType `json:"ResetType@Redfish.AllowableValues"`
   			} `json:"#Chassis.Reset"`
   		}
   	}
   	if err := json.Unmarshal(b, &t); err != nil {
   		return err
   	}
   	c.SupportedResetTypes = t.Actions.Reset.AllowedResetTypes
   	return nil
   }
   ```

3. **A full `UnmarshalJSON` replacement** only when the payload has the wrong
   shape as a whole, such as `IPMIHostInterface` sent as a bare bool. A
   replacement must fill every link and action target itself and misses any
   that later schema versions add, so use it only for types without links.

Use the `type temp T` pattern in custom decoding (as the generated code does)
so the decode does not recurse into your `UnmarshalJSON`.

## Vendor workarounds require a unit test

Every change that makes decoding or encoding accept a vendor's non-conformant
JSON needs a unit test in the same change. This covers `LenientFields`
entries, converters, `postUnmarshal` hooks written for a vendor,
`UnmarshalJSON` replacements, `MarshalJSON` changes and OEM parsing. The test:

- Decodes the vendor's payload, trimmed to the relevant properties, inline as
  a raw string literal. Name the vendor, and the firmware version if known, in
  a comment above it.
- Asserts the corrected values, not just that decoding returned no error.
- Also decodes a schema-conformant payload for the same fields, so the
  workaround is shown not to break other services.
- For writable types, checks the payload `Update()` sends, using
  `schemas.TestClient` and `CapturedCalls()`.

`TestPowerControlLenient` in `schemas/power_test.go` and
`TestIPMIHostInterfaceBool` in `schemas/computersystem_test.go` follow this
pattern. Also name the vendor and the bug in a comment on the workaround
itself, so a reader can tell why it exists.

## OEM support

Vendor extensions live in `oem/<vendor>/` and wrap the standard type:

```go
// Drive extends a schemas.Drive with Supermicro OEM fields.
type Drive struct {
	schemas.Drive
	Temperature int
}

// FromDrive returns an OEM-extended Drive.
func FromDrive(drive *schemas.Drive) (Drive, error) { ... }
```

`From<Type>` unmarshals the `Oem.<Vendor>` section from the standard object's
`RawData` (present on writable resources) or its `OEM` field. OEM actions read
their targets from `Actions.Oem` in the same payload and post through the
embedded client. `oem/smc/drive.go` is a complete example. Tests decode a
recorded payload and, for actions, use `schemas.TestClient` to check the URL
and body sent.

## Constraints

- The library module has no dependencies (`go.sum` is empty). Do not add one.
- The library targets Go 1.21; do not use newer standard library APIs outside
  `tools/`. The generator module targets Go 1.25.
- Tests must not use the network. Use inline payloads and `schemas.TestClient`.
- Keep the exported API compatible. If a change must break it (a renamed field,
  a changed type), say so explicitly in the change description.

## Commands

| Command | Use |
|---|---|
| `make test` | Unit tests with the race detector. |
| `make lint` | golangci-lint, the CI configuration (runs in Docker). |
| `make generate` | Regenerate `schemas/` and `serviceroot.go` from the pinned schema bundles. Needs network access. |
| `make check-generate` | Regenerate and fail if the committed output differs. Run it after changing generator config, generator code, or a `_custom.go` file that replaces a generated declaration. |
| `cd tools/generator && go test ./...` | Generator tests. |
